## Rehearsal and backup

Use an accepted artifact, clean disposable sample, model digest, recorded OS/hardware, runtime build and candidate SHA. Disable network before launch; keep a separate record of the network state. Start from a clean fixture and verify read results independently. For an edit, demonstrate denied permissions, explicitly authorize the minimum required rights, inspect the actual diff, run independent tests and record results; never rehearse against private code. Stop rather than misrepresent a failed run.

Record a genuine continuous rehearsal from offline launch through task completion, including the permission interaction and independent checks if qualified. Capture actual screen output, not mock screenshots. Sanitize paths, notifications, credentials, private code and logs. Keep a local video and offline slides on the presentation machine; test playback without internet. Label recorded footage with date, commit, model and hardware, and tell the audience when switching to it. If no qualifying video exists, present architecture and historical evidence instead. Do not fabricate performance or success.
